# Уведомления OpenProject в Discord

[English](README.md) | [Русский](README_RU.md)

Плагин OpenProject, который отправляет изменения пакетов работ (заданий) и
страниц Wiki в каналы Discord. Плагин доставляет настраиваемые уведомления
для каждого проекта и канала.

Discord-бот не нужен: в каждом проекте OpenProject можно указать один или
несколько вебхуков Discord и выбрать, какие события отправлять в каждый канал.

## Возможности

- **Свой канал для каждого проекта.** У проекта есть список каналов Discord
  (URL вебхуков). Каждый канал принадлежит ровно одному проекту.
- **Выбор событий для каждого канала.** Пакеты работ и Wiki настраиваются
  независимо.
- **События пакетов работ:**
  - создан;
  - изменён (любое изменение);
  - изменён статус;
  - изменён исполнитель;
  - добавлен комментарий;
  - удалён.
- **События Wiki:**
  - страница создана;
  - страница изменена;
  - страница удалена.
- **Подробные сообщения Discord** с проектом, типом задания, статусом,
  исполнителем, приоритетом, автором, списком изменённых полей и прямой
  ссылкой на OpenProject.
- **Кнопка проверки.** Отправляет тестовое сообщение в канал и показывает
  ответ Discord.
- **Журнал доставки.** Для каждого канала хранятся последние 200 попыток
  доставки — удобно для диагностики.
- **Обзор для администратора.** В админке видны все настроенные каналы
  проектов и глобальные параметры.
- **Безопасность.** Внутренние комментарии по умолчанию не отправляются.
  Упоминания в сообщениях отключены. Ошибки Discord не ломают сохранение в
  OpenProject, потому что доставка выполняется в фоновой задаче.

## Требования

- OpenProject `>= 16.0.0`
- Ruby `>= 3.4`
- PostgreSQL (стандартная база OpenProject)
- Исходящий HTTPS-доступ из контейнеров `web` и `worker` к `discord.com`

## Установка

Добавьте плагин в `Gemfile.plugins` вашей установки OpenProject. Для
воспроизводимых production-сборок фиксируйте тег релиза:

```ruby
group :opf_plugins do
  gem "openproject-discord",
      git: "https://github.com/kiriharu/openproject-discord.git",
      tag: "v0.1.0"
end
```

Установите зависимости и примените миграции плагина:

```bash
bundle install
bundle exec rails db:migrate
```

При установке через Docker эти команды нужно выполнять во время сборки
собственного образа OpenProject. Готовый образ используйте для сервисов
`web`, `worker`, `cron` и `seeder`.

После перезапуска OpenProject:

1. Откройте **Администрирование → Интеграции → Discord** и проверьте
   глобальные настройки.
2. Откройте нужный проект и включите модуль **Уведомления в Discord** в
   разделе **Настройки проекта → Модули**.
3. Откройте **Настройки проекта → Discord**.
4. Нажмите **Добавить канал**, вставьте URL вебхука Discord и выберите
   события.
5. Нажмите **Отправить тест**, чтобы проверить подключение.

## Как создать вебхук Discord

1. Откройте нужный канал в Discord.
2. Выберите **Изменить канал → Интеграции → Вебхуки → Новый вебхук**.
3. Скопируйте URL вебхука. Он выглядит так:
   `https://discord.com/api/webhooks/1234567890/abcdef...`.
4. Вставьте URL в форму канала OpenProject.

URL вебхука фактически является секретом: любой, у кого он есть, может
писать в канал. В списке каналов URL маскируется, а в базе OpenProject
хранится целиком. Используйте HTTPS и ограничьте доступ к настройкам проекта.

## Как работает выбор событий

Одна запись журнала OpenProject может порождать несколько имён событий.
Например, изменение статуса пакета работ порождает и
`work_package:updated`, и `work_package:status_changed`. Канал получает
**одно** сообщение по этой записи, если выбрано хотя бы одно из порождённых
событий.

Отсюда следует:

- **Пакет работ изменён** — приходят все изменения, включая статус,
  исполнителя и комментарии;
- только **Изменён статус** — приходят лишь изменения, содержащие смену
  статуса;
- **Пакет работ создан** не порождает дополнительное сообщение об изменении
  при создании.

OpenProject агрегирует уведомления журнала за короткий настраиваемый интервал.
Уведомления Discord используют ту же агрегацию, поэтому обычно приходят через
несколько минут после изменения, а не мгновенно.

## Глобальные настройки

**Администрирование → Интеграции → Discord** содержит:

- общий выключатель уведомлений Discord;
- имя вебхука по умолчанию;
- необязательный URL аватара;
- разрешение на отправку внутренних комментариев (по умолчанию выключено);
- разрешение на отправку фрагмента страницы Wiki (по умолчанию выключено);
- таблицу всех настроенных каналов проектов.

## Модель данных

- `discord_channels` — проект, понятное имя, URL вебхука, необязательное имя
  бота, флаг включения и JSONB-массив выбранных событий.
- `discord_deliveries` — журнал диагностики: имена событий, HTTP-статус и
  текст ответа/ошибки.

Плагин добавляет проекту связь `discord_channels`.

## Разработка и тесты

Склонируйте плагин в каталог `plugins` установки OpenProject:

```bash
git clone https://github.com/kiriharu/openproject-discord.git \
  plugins/openproject-discord
```

Укажите локальный путь в `Gemfile.plugins`:

```ruby
group :opf_plugins do
  gem "openproject-discord", path: "plugins/openproject-discord"
end
```

Запустите тесты плагина из корня OpenProject:

```bash
bundle exec rspec plugins/openproject-discord/spec
```

Тесты используют стандартную среду RSpec OpenProject, FactoryBot и WebMock.
Если плагин находится вне каталога OpenProject, задайте `OPENPROJECT_ROOT`:

```bash
OPENPROJECT_ROOT=/path/to/openproject \
  bundle exec rspec /path/to/openproject-discord/spec
```

## Диагностика

- **Сообщения не приходят.** Проверьте общий выключатель, модуль проекта,
  флаг включения канала и выбранные события. Нажмите **Отправить тест**.
- **HTTP 401/404.** Вебхук удалён или URL неверный. Создайте новый вебхук в
  Discord.
- **HTTP 429.** Discord ограничил частоту запросов. Задача повторит отправку
  с экспоненциальной задержкой.
- **Сообщения с задержкой.** OpenProject агрегирует уведомления журнала.
  При необходимости уменьшите интервал агрегации в настройках
  администрирования.
- **Не запущен worker.** Задачи доставки обрабатывает сервис `worker`
  OpenProject.
